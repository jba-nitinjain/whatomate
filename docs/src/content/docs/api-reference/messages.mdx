## Overview

The Messages API allows you to send various types of WhatsApp messages including text, media, templates, and interactive messages.

## Get Messages

Retrieve messages for a specific contact.

```bash
GET /api/contacts/{id}/messages
```

### Query Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `page` | integer | Page number (default: 1). Page 1 is the **most recent** messages. |
| `limit` | integer | Page size, 1–100. Default 50. |
| `before_id` | string | Cursor — return the `limit` messages immediately older than this message UUID. Mutually exclusive with `page`. |
| `account` | string | Restrict to one WhatsApp account. |

Messages are always returned in chronological order (oldest first) within the page.

<Aside type="caution">
  The cursor parameter is `before_id`, not `before`. There is no `after` parameter.
</Aside>

### Response

```json
{
  "status": "success",
  "data": {
    "messages": [
      {
        "id": "uuid",
        "contact_id": "uuid",
        "direction": "incoming",
        "message_type": "text",
        "content": { "body": "Hello!" },
        "media_url": "",
        "media_mime_type": "",
        "media_filename": "",
        "interactive_data": null,
        "status": "delivered",
        "wamid": "wamid.xxx",
        "error_message": "",
        "is_reply": false,
        "reply_to_message_id": null,
        "reply_to_message": null,
        "reactions": [],
        "whatsapp_account": "Main Account",
        "created_at": "2024-01-01T12:00:00Z",
        "updated_at": "2024-01-01T12:00:00Z"
      }
    ],
    "total": 100,
    "page": 1,
    "limit": 50,
    "has_more": true
  }
}
```

The field is `message_type` (not `type`), the WhatsApp ID is `wamid` (not `wa_message_id`), and
timestamps are `created_at` / `updated_at` (there is no `timestamp`). A `before_id` request returns
`messages`, `total` and `has_more` only — no `page`/`limit`.

<Aside type="note">
  Fetching a contact's messages also marks that contact's incoming messages as read as a side
  effect. Callers without `contacts:read` are restricted to contacts assigned to them, and — when
  the org enables `agent_current_conversation_only` — to messages from the contact's most recent
  chatbot session onwards.
</Aside>

## Send Text Message

Send a text message to a contact.

```bash
POST /api/contacts/{id}/messages
```

### Request Body

```json
{
  "type": "text",
  "content": {
    "body": "Hello! How can I help you today?"
  }
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `type` | string | Yes | `text` or `interactive` on this endpoint. Media is sent via `POST /api/messages/media`. |
| `content.body` | string | Yes (for text) | The message text |
| `interactive` | object | Yes (for `interactive`) | See [Send Interactive Message](#send-interactive-message) |
| `reply_to_message_id` | string | No | UUID of a message to quote-reply to. Must belong to the same contact, otherwise it is silently ignored. |
| `whatsapp_account` | string | No | Name of the WhatsApp account to send from; defaults to the contact's account |

### Response

Returns the created message object (same shape as in the list response above):

```json
{
  "status": "success",
  "data": {
    "id": "uuid",
    "contact_id": "uuid",
    "direction": "outgoing",
    "message_type": "text",
    "content": { "body": "Hello! How can I help you today?" },
    "status": "sent",
    "wamid": "wamid.xxx",
    "whatsapp_account": "Main Account",
    "created_at": "2024-01-01T12:00:00Z",
    "updated_at": "2024-01-01T12:00:00Z"
  }
}
```

## Insert External Sent Record

Persist an outbound message that was sent by another system, without sending it to WhatsApp again.

```bash
POST /api/messages/external
```

### Request Body

```json
{
  "phone_number": "919876543210",
  "whatsapp_account": "primary",
  "type": "text",
  "content": {
    "body": "Sent from external CRM"
  },
  "external_message_id": "crm-msg-123",
  "whatsapp_message_id": "wamid.HBg...",
  "sent_at": "2026-03-27T10:30:00Z"
}
```

### Notes

- Provide either `contact_id` or `phone_number`
- If `phone_number` is used, the contact is created automatically if needed
- The message is stored with status `sent`
- This endpoint does not call the WhatsApp API
- A super admin API key can target another organization by adding `X-Organization-ID: <org-uuid>`
- If a super admin sends `phone_number_id`, Whatomate resolves the WhatsApp account from that phone ID before contact lookup and stores the message in that account's organization
- If `phone_number_id` is ambiguous across organizations, send `X-Organization-ID` explicitly
- To record a template sent by another system, set `type` to `template`, send `template_name`, and optionally send `template_params`, `phone_number_id`, and template header media fields

### Response

```json
{
  "status": "success",
  "data": {
    "id": "uuid",
    "contact_id": "uuid",
    "direction": "outgoing",
    "message_type": "text",
    "content": {
      "body": "Sent from external CRM"
    },
    "status": "sent",
    "wamid": "wamid.HBg..."
  }
}
```

### External Template Example

```bash
curl -X POST "https://your-whatomate-server/api/messages/external" \
  -H "X-API-Key: whm_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "contact_id": "9d7cb4e2-6e85-4f46-95bd-3ea4132c8123",
    "phone_number_id": "116800811516809",
    "type": "template",
    "template_name": "credentials_v1",
    "template_params": {
      "name": "Nitin Jain",
      "portal": "Income Tax"
    },
    "header_media_url": "https://cdn.example.com/template-header.jpg",
    "header_media_mime_type": "image/jpeg",
    "header_media_filename": "template-header.jpg",
    "whatsapp_message_id": "wamid.external-template-123"
  }'
```

<Aside type="note">
  A legacy `POST /api/messages` route is kept for backwards compatibility. It
  maps to the same handler as `POST /api/contacts/{id}/messages` and expects the
  same request body. Prefer the contact-scoped endpoint for new integrations.
</Aside>

## Send Template Message

Send a pre-approved template message.

```bash
POST /api/messages/template
```

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `contact_id` | string | One of contact_id or phone_number | UUID of existing contact |
| `phone_number` | string | One of contact_id or phone_number | Phone number (creates contact if not exists) |
| `phone_number_id` | string | No | Meta phone number ID used to resolve the WhatsApp account directly |
| `template_name` | string | One of template_name or template_id | Name of the template |
| `template_id` | string | One of template_name or template_id | UUID of the template |
| `template_params` | object | No | Named or positional body parameters |
| `header_params` | object | No | Value for a TEXT header with a `{{var}}` (max 1). Keyed by the variable's name for named templates, or `"1"` for positional. Falls back to `template_params` if omitted. |
| `button_params` | object | No | Dynamic URL button parameters (button index → value) |
| `account_name` | string | No | Specific WhatsApp account to use |
| `status_callback_url` | string | No | URL that receives delivery status updates for this message (`sent`, `delivered`, `read`, `failed`) |
| `status_callback_bearer_token` | string | No | Sent back as `Authorization: Bearer <token>` on every status callback |

### Examples

**Using phone number (creates contact if needed):**

```bash
curl -X POST "https://your-whatomate-server/api/messages/template" \
  -H "X-API-Key: whm_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "phone_number": "919876543210",
    "template_name": "hello_world"
  }'
```

```json
{
  "phone_number": "919876543210",
  "template_name": "hello_world"
}
```

**External system minimal payload:**

If an external system wants Whatomate to send the template directly, this is the simplest contract:

```bash
curl -X POST "https://your-whatomate-server/api/messages/template" \
  -H "X-API-Key: whm_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "phone_number": "919876543210",
    "phone_number_id": "116800811516809",
    "template_name": "credentials_v1",
    "template_params": {
      "name": "Nitin Jain",
      "portal": "Income Tax"
    }
  }'
```

Notes:

- `phone_number` is the recipient
- `phone_number_id` tells Whatomate which WhatsApp account should send the template
- `template_params` is optional and should contain the dynamic field values expected by the template
- if the contact does not exist yet, Whatomate creates it automatically

**With template header media URL:**

```bash
curl -X POST "https://your-whatomate-server/api/messages/template" \
  -H "X-API-Key: whm_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "phone_number": "919876543210",
    "phone_number_id": "116800811516809",
    "template_name": "credentials_v1",
    "template_params": {
      "name": "Nitin Jain",
      "portal": "Income Tax"
    },
    "header_media_url": "https://cdn.example.com/template-header.jpg"
  }'
```

**With named parameters:**

If your template has placeholders like `Hello {{name}}, your order {{order_id}} is ready`:

```json
{
  "contact_id": "uuid",
  "template_name": "order_confirmation",
  "template_params": {
    "name": "John",
    "order_id": "12345"
  }
}
```

**With positional parameters:**

```json
{
  "phone_number": "919876543210",
  "template_name": "order_confirmation",
  "template_params": {
    "1": "John",
    "2": "12345"
  }
}
```

**With a TEXT header variable:**

Meta allows at most one variable in a TEXT header. If your template's header is `Our {{season}} sale is on!`, supply the value via `header_params`:

```json
{
  "phone_number": "919876543210",
  "template_name": "seasonal_promotion",
  "header_params": {
    "season": "Summer"
  },
  "template_params": {
    "customer_name": "John",
    "discount": "25%"
  }
}
```

For a positional header (`Our {{1}} sale is on!`), use `"1"` as the key. If you omit `header_params`, the value is looked up in `template_params` by the same name — convenient for named templates where the header variable doesn't collide with a body variable.

**With URL button parameters:**

If your template has a URL button with a dynamic variable (e.g., `https://example.com/track/{{1}}`), provide the dynamic value via `button_params`. The key is the button index (starting from `"0"`):

```json
{
  "contact_id": "uuid",
  "template_name": "order_shipped",
  "template_params": {
    "name": "John",
    "order_id": "12345"
  },
  "button_params": {
    "0": "12345"
  }
}
```

<Aside type="note">
  The `button_params` key corresponds to the button's position index in the template (zero-based). For example, if the first button is a URL button with `{{1}}`, use `"0"` as the key. The value replaces the dynamic part of the URL.
</Aside>

### Response

```json
{
  "status": "success",
  "data": {
    "id": "uuid",
    "contact_id": "uuid",
    "direction": "outgoing",
    "message_type": "template",
    "content": {
      "body": "Hello John, your order 12345 is ready"
    },
    "status": "pending",
    "is_reply": false,
    "whatsapp_account": "primary",
    "created_at": "2026-03-27T10:30:00Z",
    "updated_at": "2026-03-27T10:30:00Z"
  }
}
```

`"status": "pending"` means the request was accepted and queued — not that the message has been sent. Store the returned `id`: it is the `message_id` in every status callback.

<Aside type="tip">
  When using `phone_number`, a new contact is automatically created if one doesn't exist for that number.
</Aside>

<Aside type="caution">
  If required template parameters are missing, you'll receive an error:
  `"Missing template parameters: name, order_id. Expected parameters: [name, order_id]"`
</Aside>

### Delivery Status Callback

The response above confirms only that the request was accepted — `"status": "pending"` means queued, not sent. Supply `status_callback_url` if the calling system needs to know what actually happened to the message.

```bash
curl -X POST "https://your-whatomate-server/api/messages/template" \
  -H "X-API-Key: whm_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "phone_number": "919876543210",
    "template_name": "order_confirmation",
    "template_params": { "name": "John", "order_id": "12345" },
    "status_callback_url": "https://billing.example.com/api/whatsapp-status",
    "status_callback_bearer_token": "your-secret-token"
  }'
```

Whatomate then POSTs this body to that URL every time the status changes:

```json
{
  "message_id": "12415f80-1d08-4c17-9030-08302bdf37a6",
  "whatsapp_message_id": "wamid.HBgMOTE5ODc2NTQzMjEwFQIAERgS",
  "status": "sent",
  "contact_id": "4c0a7f45-7d2f-4a7f-9a3c-1b0f6c4e5e20",
  "contact_phone": "919876543210",
  "contact_name": "Nitin Jain",
  "whatsapp_account": "Main Account",
  "template_name": "order_confirmation",
  "timestamp": "2026-06-09T10:30:00Z"
}
```

Only `message_id`, `status` and `timestamp` are always present. Any other field is omitted when Whatomate has no value for it — notably `error_message` (only on `failed`), `whatsapp_message_id` (missing when the send failed before WhatsApp accepted it), and `contact_name` (missing for an auto-created contact whose profile name is unknown). `timestamp` is UTC.

| Status | Meaning |
|--------|---------|
| `sent` | WhatsApp accepted the message. Not proof of delivery. |
| `delivered` | The message reached the recipient's device. |
| `read` | The recipient opened the message. Only reported when the recipient has read receipts enabled. |
| `failed` | The message did not go out, or WhatsApp rejected it after accepting it. `error_message` explains why. |

Notes:

- Both fields are optional. Omit them and no callbacks are sent.
- `status_callback_url` must be an absolute `http://` or `https://` URL, otherwise the request is rejected with `400`.
- Your endpoint must be reachable from the public internet. Whatomate refuses to call private or internal addresses (`localhost`, `127.0.0.1`, `10.x`, `192.168.x`, `*.internal`, `*.local`); such a URL is accepted at send time but every callback to it fails.
- `pending` is never sent as a callback.
- Statuses only move forward, and each is normally sent once — make your endpoint idempotent, since WhatsApp can repeat its own notifications. `failed` can arrive after `sent` or `delivered`.
- Reply with any `2xx`. A non-`2xx` is logged and never retried; in-flight callbacks are lost if Whatomate restarts.
- The token is stored with the message so late `delivered`/`read` callbacks can still be authenticated — rotating it affects new sends only.
- Callbacks are best effort: failures are logged, not retried, and never affect the WhatsApp message.
- Validation errors (missing template, bad parameters) are returned on the original request; no callback is sent because no message was created.
- For multipart requests, send both values as ordinary text form fields.

<Aside type="caution">
  `sent` is not the same as delivered. A message can be reported `sent` and then turn `failed` minutes later — invalid number, blocked business, or an expired messaging window. Treat `delivered` as the first proof the message actually arrived.
</Aside>

## Check Message Status

Because status callbacks are never retried, you can also ask for the current status at any time. Use this when a callback did not arrive, after your own system was down, or as a periodic reconciliation. It works for every message, including ones sent without a `status_callback_url`.

### One message

```bash
GET /api/messages/{id}/status
```

`{id}` accepts either the Whatomate message UUID or the WhatsApp message ID (`wamid...`).

```bash
curl "https://your-whatomate-server/api/messages/12415f80-1d08-4c17-9030-08302bdf37a6/status" \
  -H "X-API-Key: whm_your_api_key"
```

```json
{
  "status": "success",
  "data": {
    "message_id": "12415f80-1d08-4c17-9030-08302bdf37a6",
    "whatsapp_message_id": "wamid.HBgMOTE5ODc2NTQzMjEwFQIAERgS",
    "status": "delivered",
    "contact_id": "4c0a7f45-7d2f-4a7f-9a3c-1b0f6c4e5e20",
    "contact_phone": "919876543210",
    "contact_name": "Nitin Jain",
    "whatsapp_account": "Main Account",
    "template_name": "credentials_v1",
    "direction": "outgoing",
    "created_at": "2026-06-09T10:30:00Z",
    "updated_at": "2026-06-09T10:30:04Z"
  }
}
```

Field names match the status callback body exactly, so one parser handles both. `status` can additionally be `pending` here, meaning the message has not left Whatomate yet.

### Several messages

```bash
POST /api/messages/status
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `message_ids` | string[] | One of the two | Whatomate message UUIDs |
| `whatsapp_message_ids` | string[] | One of the two | WhatsApp message IDs (`wamid...`) |

Up to 100 IDs per call, and the two lists may be mixed.

```bash
curl -X POST "https://your-whatomate-server/api/messages/status" \
  -H "X-API-Key: whm_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "message_ids": ["12415f80-1d08-4c17-9030-08302bdf37a6"],
    "whatsapp_message_ids": ["wamid.HBgMOTE5ODc2NTQzMjEwFQIAERgS"]
  }'
```

Unknown IDs are returned in `not_found` rather than failing the request:

```json
{
  "status": "success",
  "data": {
    "statuses": [{ "message_id": "12415f80-1d08-4c17-9030-08302bdf37a6", "status": "delivered" }],
    "not_found": ["wamid.HBgMOTE5ODc2NTQzMjEwFQIAERgS"]
  }
}
```

Notes:

- Duplicate IDs are returned once.
- More than 100 IDs returns `400`; neither list supplied returns `400`.
- Results are scoped to your own organization — anything else is reported as not found.
- An unknown ID on the single-message endpoint returns `404 Message not found`.

<Aside type="tip">
  Use callbacks as the normal path and lookups as the safety net. Polling every message on a timer adds load for no benefit — look up only what you never heard about.
</Aside>

## Send Media Message

Upload and send an image, video, document, or audio message.

```bash
POST /api/messages/media
```

<Aside type="caution">
  This endpoint takes **`multipart/form-data` with a file upload**, not JSON. There is no
  `media_url` field — the file is uploaded to Whatomate, which then sends it to Meta.
</Aside>

### Form Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `contact_id` | text | Yes | UUID of the recipient contact |
| `file` | file | Yes | The media file |
| `type` | text | No | `image` (default), `video`, `audio`, or `document` |
| `caption` | text | No | Caption text |
| `whatsapp_account` | text | No | Account to send from; defaults to the contact's account |

```bash
curl -X POST "http://your-server:8080/api/messages/media" \
  -H "X-API-Key: whm_your_api_key" \
  -F "contact_id=<uuid>" \
  -F "type=image" \
  -F "caption=Check out this product!" \
  -F "file=@./product.jpg"
```

Meta's own size limits apply (roughly 5 MB images, 16 MB audio/video, 100 MB documents); Whatomate
does not enforce its own cap.

### Response

Returns the same message object shape as the other send endpoints:

```json
{
  "status": "success",
  "data": {
    "id": "uuid",
    "contact_id": "uuid",
    "direction": "outgoing",
    "message_type": "image",
    "content": { "body": "Check out this product!" },
    "media_url": "images/…",
    "media_mime_type": "image/jpeg",
    "media_filename": "product.jpg",
    "status": "sent",
    "whatsapp_account": "Main Account",
    "created_at": "2024-01-01T12:00:00Z",
    "updated_at": "2024-01-01T12:00:00Z"
  }
}
```

## Send Interactive Message

Send interactive messages with buttons, CTA URLs, WhatsApp Flows, or a Call button.

```bash
POST /api/contacts/{id}/messages
```

The `interactive.type` selects the variant:

| `interactive.type` | Fields used |
|---|---|
| `button` | `body`, `buttons: [{id, title}]` |
| `list` | `body`, `button_text` |
| `cta_url` | `body`, `button_text`, `url` |
| `flow` | `flow_id` (required), `body`, `button_text` (CTA label, default `"Open"`), `header`, `first_screen` |
| `voice_call` | `body`, `display_text`, `ttl_minutes` |

### Button Message

Send a message with up to 3 quick reply buttons:

```bash
curl -X POST "https://your-whatomate-server/api/contacts/{contact_id}/messages" \
  -H "X-API-Key: whm_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "interactive",
    "interactive": {
      "type": "button",
      "body": "How would you like to proceed?",
      "buttons": [
        { "id": "yes", "title": "Yes" },
        { "id": "no", "title": "No" }
      ]
    }
  }'
```

```json
{
  "type": "interactive",
  "interactive": {
    "type": "button",
    "body": "How would you like to proceed?",
    "buttons": [
      { "id": "yes", "title": "Yes" },
      { "id": "no", "title": "No" }
    ]
  }
}
```

{
  "type": "interactive",

    "type": "cta_url",
    "body": "Click below to view your order details",
    "button_text": "View Order",

### WhatsApp Flow

```json
{
  "type": "interactive",
  "interactive": {
    "type": "flow",
    "flow_id": "<meta_flow_id>",
    "header": "Order form",
    "body": "Tap below to place your order",
    "button_text": "Open form",
    "first_screen": "WELCOME"
  }
}
```

The flow must belong to your organization, otherwise `400 Flow not found for this organization`.
Omitting `flow_id` returns `400 flow_id is required to send a flow`.

### Voice Call Button

```json
{
  "type": "interactive",
  "interactive": {
    "type": "voice_call",
    "body": "Need help? Call us.",
    "display_text": "Call support",
    "ttl_minutes": 60
  }
}
```

Requires the sending account to have Business Calling enabled, otherwise the request is rejected
with `400`. When the recipient taps the button, the resulting inbound call is sticky-routed back to
the agent who sent it — the routing payload is stamped server-side from the authenticated user and
is never read from the request body.

### Response

Returns the created message object. `interactive_data` carries the rendered interactive payload.

```json
{
  "status": "success",
  "data": {
    "id": "uuid",
    "contact_id": "uuid",
    "direction": "outgoing",
    "message_type": "interactive",
    "content": { "body": "How would you like to proceed?" },
    "interactive_data": { },
    "status": "sent",
    "is_reply": false,
    "whatsapp_account": "Main Account",
    "created_at": "2024-01-01T12:00:00Z",
    "updated_at": "2024-01-01T12:00:00Z"
  }
}
```

<Aside type="note">
  Button titles have a maximum length of 20 characters. Button IDs are returned when the user clicks a button.
</Aside>

## Send Reaction

Add or remove an emoji reaction on a specific message.

```bash
POST /api/contacts/{id}/messages/{message_id}/reaction
```

### Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `emoji` | string | Yes | The emoji to react with. Send an empty string (`""`) to remove your existing reaction. |

```json
{
  "emoji": "👍"
}
```

Each user may have only one reaction per message; sending a new emoji replaces
the previous one from the same user.

### Response

```json
{
  "status": "success",
  "data": {
    "message_id": "uuid",
    "reactions": [
      {
        "emoji": "👍",
        "from_user": "user-uuid"
      }
    ]
  }
}
```

## Mark Conversation as Read

Mark all incoming messages from a contact as read. When the account has
auto read receipts enabled, read receipts are also sent to WhatsApp.

```bash
POST /api/contacts/{id}/mark-read
```

### Response

```json
{
  "status": "success",
  "data": {
    "status": "ok"
  }
}
```

## Mark Message as Read

```bash
PUT /api/messages/{id}/read
```

  **Not implemented.** This route is registered but currently returns
  `501 Not implemented yet`. Use [Mark Conversation as Read](#mark-conversation-as-read)
  (`POST /api/contacts/{id}/mark-read`) instead.
</Aside>

## Download Media

Stream the media attached to a message. Returns the raw file bytes with the stored MIME type — not
a JSON envelope.

```bash
GET /api/media/{message_id}
```

Returns `404 No media found` when the message has no attachment. Callers without `contacts:read`
may only fetch media for contacts assigned to them, or for contacts with an active transfer to a
team they belong to — otherwise `403 Access denied`.

## Message Status

Messages go through the following status flow:

| Status | Description |
|--------|-------------|
| `pending` | Message queued for sending |
| `sent` | Message sent to WhatsApp servers |
| `delivered` | Message delivered to recipient's device |
| `read` | Message read by recipient |
| `failed` | Message failed to send |
| `received` | Set on inbound messages |

Valid `message_type` values are `text`, `image`, `video`, `audio`, `document`, `template`,
`interactive`, `flow`, `reaction`, `location`, and `contact`.

<Aside type="note">
  Organisation webhooks fire on `message.sent` only. To receive `delivered`, `read`, and `failed` for a specific message, send `status_callback_url` with the send request — see [Delivery Status Callback](#delivery-status-callback) above.
</Aside>
